# DECISIONS - lightweight decision log (newest first)

Big, long-lived choices get an ADR in `docs/adr/`. Everything else gets one entry here:
- **what** was decided;
- **why**;
- **alternatives** considered;
- **revisit when** (the condition that would reopen it).

| 2026-11-08 | Manual trial control is a user-intent event (`UserTrialControl` start/stop) handled by `MatchStateMachine`, which marks the resulting `MatchStateChanged.manual=True` and ignores screen observations until stop, a verified log `match_end`, or process exit. | The pane must be usable in M1-M2 with no automatic detection, and later the player's word must beat a noisy classifier. | A bridge-only hack that publishes `MatchStateChanged` directly; a settings flag. | When M3 detection hits 98 % per-second accuracy, consider auto-ending manual trials on a confident tally screen. |
| 2026-11-08 | `MatchStateMachine` is attached in every run mode and *adopts* any `MatchStateChanged` it did not publish itself (identity check on the last published event). | Demo and replay publish states directly; without adoption a manual Stop in demo was a no-op because the machine still believed MENU. | Attach only in live mode with a separate demo fallback path (two code paths); add a `source` field to the event. | If a second publisher of `MatchStateChanged` appears in live mode. |
| 2026-11-08 | The dashboard stays visible during a manual trial (and demo); detected trials hide it. | The Stop button lives on the dashboard; the pane is click-through and must stay text-free. | A Stop hotkey; a tray menu (M7). | When a tray icon exists (M9), move Stop there too. |
